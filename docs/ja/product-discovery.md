# Customer Discovery｜日常のニーズからプロダクトへ

[English](../en/product-discovery.md) | [日本語](./product-discovery.md) ・ [ポートフォリオTOP](../../README.ja.md)

## 観察した課題

電車に関心がある子どもは、路線図を見ながら駅名を繰り返し読み上げてもらうことを楽しみます。一方で、保護者が家事などで手が離せず、その場で読み上げられないこともあります。

**「好きな路線の駅名を、子ども自身が好きなタイミングで聞けるようにする」**ことをプロダクトの目的として定義しました。

## ユーザーのジョブ

> 自分の好きな路線の駅を選んで、名前を何度でも聞き、電車の移動を楽しみたい。

読字能力や複雑な操作に依存せず、音声と視覚的な反応を通じて楽しめる体験を目指しました。

## ニーズから要件への変換

| ユーザーニーズ | プロダクトでの対応 |
| --- | --- |
| 好きな駅名を聞きたい | 駅をタップすると即時読み上げ |
| 特定の路線で遊びたい | 路線を選択して駅の並びを確認 |
| 車内アナウンスを楽しみたい | 「つぎへ」による次駅案内 |
| 電車が進む様子を見たい | 走行・停車の視覚的な表現 |
| 幼児でも操作したい | シンプルな操作と視覚・音声フィードバック |

## 初期利用者からの反応

利用した子どもたちからは、次のような言葉がありました。

> 「やまのてせんやりたい」

> 「うちの近くの路線読み上げたい」

これらの反応から、**路線の選択肢の豊富さに加え、自分にとって身近な路線を選べること**が価値になると確認しました。

## この事例で示す能力

**Customer Discovery / Problem Framing / Product Strategy / Requirements Definition / User-Centered Design**

機能ありきで開発するのではなく、ユーザーの行動から解決すべき課題を定義し、具体的なUXへ落とし込むアプローチです。
