## 開発の背景｜日常のニーズをプロダクトへ

電車が好きな子どもは、路線図を見ながら駅名を何度も読み上げてほしがることがあります。しかし、保護者は家事などで手が離せず、すぐには対応できない場面もあります。

**「大人がその場にいなくても、子ども自身が好きな路線や駅を選び、駅名を聞いて楽しめる仕組みがあればよいのではないか」**

この課題を起点に、路線図上の駅をタップすると駅名を読み上げ、「つぎへ」で車内アナウンス風に次の駅を案内するアプリ「えきよみ」を企画・公開しました。

利用した子どもたちからは、「やまのてせんやりたい」「うちの近くの路線読み上げたい」といった声もあり、**利用者にとって身近な路線を自分で選択できること**の価値を確認しました。

このプロジェクトで実証したかったのは、単に機能を実装できることではありません。**ユーザーニーズの発見から要件への変換、AIを組み合わせた実装・レビュー、品質改善、リリースまでを推進できること**です。

## プロダクト概要

| 項目 | 実績 |
| --- | --- |
| **プロダクト** | 幼児向け電車路線・駅名読み上げアプリ |
| **収録範囲** | 東京を走る**88路線・延べ1,564駅** |
| **提供プラットフォーム** | **Web・iOS**の2プラットフォーム |
| **主な機能** | 駅名読み上げ、次駅アナウンス、電車の走行・停車表現 |
| **開発プロセス** | Claude Codeによる実装、Codexによる独立レビュー、GitHubによる変更管理 |
| **担当領域** | 課題発見、プロダクト企画、要件定義、AI活用設計、品質管理、リリース推進 |

## 強みを示す4つのケーススタディ

### 01｜Customer Discovery — 顧客課題をプロダクトに転換

「駅名を読んでほしい」という反復的なニーズに着目。幼児が自力で路線を選び、操作と音声を通じて楽しめる体験を設計しました。子どもたちの具体的な反応から、好きな路線や身近な路線を選ぶ価値も確認しています。

**訴求能力：** ニーズ発見、課題設定、要件定義、ユーザー体験設計

[Product Discoveryの詳細](./docs/ja/product-discovery.md)

### 02｜AI Orchestration — 複数AIを役割分担して開発を推進

Claude Codeを実装・改善に、Codexを独立した品質レビューに活用。人間がプロダクト方針・優先順位・採否を判断し、GitHubで変更履歴と対応を管理しました。

**訴求能力：** AIオーケストレーション、プロジェクト推進、実装管理、意思決定

[AI Orchestrationの詳細](./docs/ja/ai-orchestration.md)

### 03｜Quality Management — AIのレビューを品質改善につなぐ

Codexのレビューで抽出された**10項目の改善事項**を、Claude Codeでの修正・検証につなげました。対象は保護者向け導線、アクセシビリティ、視認性、操作性、路線情報の正確性、iOSビルドなどです。

**訴求能力：** 品質保証、レビュー設計、指摘の要件化、トレーサビリティ

[Quality Managementの詳細](./docs/ja/quality-management.md)

### 04｜Product Iteration — 継続改善とプロダクト判断

初回チュートリアル、音声選択、連続再生、アプリアイコンの改善を推進。機能単位の実装だけでなく、対象ユーザーに適した操作体験とWeb・iOSでの一貫性を重視しました。

**訴求能力：** Product Leadership、UX、優先順位付け、継続改善

[Product Iterationの詳細](./docs/ja/product-iteration.md)

## AIを活用したデリバリーモデル

```text
ユーザーニーズの発見
        ↓
プロダクト方針・要件・優先順位の判断［Human］
        ↓
機能実装・改善［Claude Code］
        ↓
独立した品質レビュー［Codex］
        ↓
修正・確認事項の整理［Claude Code］
        ↓
採否・品質・リリース判断［Human］
        ↓
GitHubによる変更管理 → Web・iOS公開
```

※ 実際に記録された開発・レビュー・改善の役割分担をモデル化したもので、完全自律型のAIエージェントシステムが常時稼働していたことを意味しません。
